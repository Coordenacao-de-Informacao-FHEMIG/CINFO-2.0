Apresentação Estratégica

PROJETO CINFO 2.0

A revolução na forma de gerir dados para a saúde de Minas Gerais.

O Incidente Crítico

05 de Maio: Consultas de BI levaram à indisponibilidade do ambiente FHEPROD.

O incidente forçou a intervenção imediata da GTIC e Phillips, expondo o risco de manter o BI conectado diretamente ao banco de produção assistencial.

Diagnóstico: Por que o sistema travou?

O Tasy (OLTP) foi desenhado para operações rápidas e pontuais (inserir evoluções, checar prescrições). Não para análise de milhões de registros simultâneos.

A Metáfora do Restaurante: Tentar contar cada grão de feijão no estoque enquanto os chefs cozinham. Você paralisa a cozinha (Produção) e entrega a conta com atraso (Análise).

Arquitetura Atual (Errada)

  • Conexão Direta: ERP → Power BI.
  • Disputa de Recursos: BI disputa CPU e Disco com o atendimento clínico.
  • Processos Manuais: Alterações diretas em arquivos PBIX e falta de versionamento.

A Solução: CINFO 2.0

O projeto propõe a criação de camadas intermediárias (Staging) para proteger o hospital e garantir a agilidade da informação.

Nova Arquitetura (Correta)

ERP → STAGING / ODS → Power BI

  • Extração controlada (madrugada) para metatabelas otimizadas.
  • Atualização incremental (apenas dados novos/recentes).
  • Proteção total da operação assistencial.

Novas Ferramentas: PBI DataFlows

O uso de Power BI DataFlows permite que as transformações de dados ocorram na nuvem, de forma independente do relatório final.

  • Query Folding: Processamento extremamente veloz.
  • Reutilização: Um único fluxo de dados serve a vários painéis (BE, Leitos, FF).
  • Padronização: Garantia de que a regra de negócio é a mesma para todos.
